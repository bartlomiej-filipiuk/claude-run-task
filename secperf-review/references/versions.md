## drupal-security

Checked this session against drupal.org and api.drupal.org (2026-09-29). CONFIRMED: SA-CORE-2026-004 (PostgreSQL-only SQLi, CVE-2026-9082, fixed 10.4.10/10.5.10/10.6.9/11.1.10/11.2.12/11.3.10); SA-CORE-2026-005 (JSON:API PHP object injection, needs JSON:API write enabled plus a field type with serialized properties, no core field type qualifies); SA-CORE-2026-007 (rebuild.php does not check Host header against trusted_host_patterns); SA-CORE-2026-008 (Media oEmbed URL discovery SSRF; settings key is $settings['media_oembed_discovery_trusted_host_patterns'], regex list); SA-CORE-2026-009 (JSON:API/REST image upload lacks MIME validation); 005/007/008/009 fixed in 10.5.12/10.6.11/11.2.14/11.3.12; SA-CORE-2025-008 (private/temporary files with Cache-Control: public, needs a custom/contrib module handling non-public files); accessCheck change record (content entities only, not config entities, deprecated 9.2, exception in 10); TrustedRedirectResponse constructor trusts the URL; FileUploadHandler::handleExtensionValidation behaves exactly as described; file_validate_* deprecated 10.2.0 (the change record says removed in 11.x without a precise minor); Condition::compile operator check and escapeField; PermissionAccessCheck (comma = AND, plus = OR); user.logout CSRF since 10.3 with _csrf_confirm_form_route; _csrf_request_header_token always passes for anonymous and only applies to non-safe methods. CORRECTED: (1) SA-CORE-2026-011 affects 11.2.x with no fix (EOL), 11.3.0-11.3.13 and 11.4.0-11.4.3; 10.6.x only got hardening; it is a flaw in core's XSS filter, not in AJAX commands. (2) SA-CORE-2025-004 is Link field attribute XSS needing edit access through web services, not javascript: hrefs. (3) SA-CORE-2024-004 is email uniqueness (case-insensitive), not username. (4) Url::fromUri('javascript:...') throws InvalidArgumentException in UnroutedUrlAssembler, so it is not an XSS sink by itself. (5) allow_insecure_uploads is config system.file, not $settings. (6) The '!' placeholder is not supported in current core: E_USER_WARNING and the argument is dropped; the pack said 'removed in Drupal 8'. (7) FormSubmitter::redirectForm uses a plain RedirectResponse, so form_state->setRedirectUrl(external) is blocked by core, not an open redirect. (8) Xss::filterAdmin allows all body tags except script and style; the 'forms' claim was not confirmed. (9) Composer 2.9 blocks packages with advisories by default (audit.block-insecure), so roave/security-advisories is no longer the recommended guard. NOT VERIFIED (kept as assumptions): gadget-chain SA numbers 2024-006/007/008, 2025-003, 2025-006, 2026-002, 2026-006 (summarizer only, drop the specific IDs from the skill text); SA-CORE-2026-013; whether Views field handlers enforce field access on mail; hx-on:* execution in Drupal's HTMX integration; 11.0.0 as the exact removal version of file_validate_*. Hard-coded fixed-version numbers must not be baked into the skill; it should run composer audit or compare with drupal.org/security at review time.

## drupal-perf-cache

Re-verified against Drupal 11.x, 11.2.x, 10.4.x, 10.5.x and 10.6.x source on git.drupalcode.org plus the cited change records and issues. Confirmed as written: renderer.config defaults; page_cache_kill_switch tagged for both page_cache_response_policy and dynamic_page_cache_response_policy; Messenger::addMessage() calls killSwitch->trigger() unconditionally; PageCache::storeResponse ignores max-age and refuses non-CacheableResponseInterface; NoSessionOpen; PrivateTempStore starts an owner key in the session for anonymous users; DynamicPageCacheSubscriber::shouldCacheResponse (refuses when max-age is not permanent and <= 0, or when a session/user context remains); BlockViewBuilder uses #lazy_builder except main content and title blocks; getBundleListCacheTags exists and EntityBase adds bundle list tags on save; Renderer lazy builder asserts and allowed keys; doTrustedCallback semantics; Renderer::renderPlain deprecated in 10.3.0, removed in 12.0.0; LruMemoryCache with entity.memory_cache.slots 1000 from 11.2.0 (10.5.x still uses unbounded MemoryCache); State is a CacheCollector (10.3 opt-in, state_cache removed in 11.0); DatabaseBackend::DEFAULT_MAX_ROWS 5000 with database_cache_max_rows; ClientFactory timeout 30; dblog row_limit 1000; Views Random sort uses UncacheableDependencyTrait; exposed filters add the 'url' context (FilterPluginBase); PagerPluginBase returns url.query_args; JSON:API OffsetPage::SIZE_MAX is 50.
Corrections made: (1) CacheableMetadata::addCacheableDependency() with a non-cacheable object is deprecated since 11.2.0 (required in 12.0), and Renderer::addCacheableDependency() since 11.3.0 (type error in 13.0), see change record 3525389; the max-age 0 behaviour still applies today. (2) A lazy builder can return a #type render array from 10.5 and 11.2 only. It is NOT available in 10.4, 11.0 or 11.1 (checked in Renderer.php on each branch). (3) The cachetags purge (CacheTagsPurgeInterface / DatabaseCacheTagsChecksum::purge) exists in 11.2.x and later, not in 10.5.x or 10.6.x, and only runs on a full cache rebuild. (4) A QueueWorker with no 'cron' key is not processed by cron at all (Cron::processQueues skips it), so the old signal 'QueueWorker without cron time when heavy' was wrong. (5) CacheOptionalInterface exists from 10.5 and 11.1, not only 11.x. (6) The #[TrustedCallback] method attribute is an alternative to TrustedCallbackInterface (present since 10.3), and service-method strings for lazy builders are valid. (7) Early rendering with render() inside an active render context (preprocess, formatters) bubbles metadata correctly; only renderInIsolation/renderPlain/renderRoot and controller early rendering lose or leak it. (8) Issue 2966607 is about cachetags deadlocks in transactions, not deduplication. (9) DPERF-22 rests on issue 2660002, which is still 'Needs work', so treat it as a known limitation, not a documented rule. Still not verified: current Drupal 11 minor number, Drupal 10 end-of-life date.

## nextjs-perf-cache

Verified in this session against nextjs.org docs 16.3.6 (pages updated Mar to Sep 2026), the Next 15 and Next 16 release posts, the 14.x/15.x/16.x GitHub advisories, and the Sept 22 2026 security post. The pack's version facts hold up: fetch default 'auto no cache' in 15+, GET Route Handlers uncached from 15, staleTimes.dynamic 30 s to 0 in 15, force-dynamic sets no-store on fetch (15 breaking list), revalidateTag/revalidatePath during render throws (15), after() stable 15.1, Node middleware stable 15.5, proxy.ts in 16 (middleware deprecated, Edge only), revalidateTag(tag, profile) with single-arg deprecated (acts like {expire: 0}, works only with TS errors suppressed), updateTag Server Actions only, use cache default profile 5 min stale / 15 min revalidate / never expire, prerender exclusion thresholds (revalidate 0, expire under 5 min, stale under 30 s), tag limits 256 chars and 128 tags, images.qualities default [75] (required in 16), minimumCacheTTL 14400, maximumRedirects 3, priority deprecated for preload, and dynamic/revalidate/fetchCache/dynamicParams unavailable with cacheComponents. Corrections and caveats: (1) The pack's security floor is stale. Since May 2026 there are RSC and fetch cache-poisoning advisories (CVE-2026-44576, CVE-2026-44582, CVE-2026-64648, CVE-2026-64647) and Aug/Sep 2026 RCEs in the image optimizer (AVIF, fixed 15.5.24/16.3.3) and next/og ImageResponse (fixed 16.3.6). Current patched lines per the Sept 22 2026 post are 16.3.6 and 15.5.26; 13.x and 14.x get no patches, so 14.2.31 or 15.4.5 are no longer acceptable floors. CVE-2025-49826 affects >=15.0.4-canary.51 <15.1.8 (not only 15.1.0 to 15.1.7). (2) 'use cache' captures closure variables into its cache key automatically (docs, Cache keys), unlike unstable_cache, so the user-keyed leak signal applies mainly to unstable_cache and to identity read from non-Next sources. (3) staleTimes and optimizePackageImports are still labelled experimental in 16.3.6. (4) Route Handlers get no fetch memoization. (5) Under Partial Prefetching (opt-in, `partialPrefetching`) prefetch={true} costs a server invocation per link; the default Link prefetch on dynamic routes only goes down to the nearest loading.js. (6) Several items (NPERF-04, NPERF-16) depend on repo context that a diff does not show; the skill should ask for or grep the repo rather than judge from the diff alone.

## wcag

Checked this session against primary sources. CONFIRMED: eslint-config-next 16.3.6 (unpkg dist/index.js) enables exactly six jsx-a11y rules as warn: alt-text (elements img, img: Image), aria-props, aria-proptypes, aria-unsupported-elements, role-has-required-aria-props, role-supports-aria-props. Next docs list only five (they omit alt-text). eslint-plugin-jsx-a11y 6.10.2 peer eslint is ^3..^9 (no ESLint 10). Using ARIA has four rules; rule 4 covers focusable elements and also ancestors that contain visible interactive children. ARIA 1.2 prohibits naming (aria-label/aria-labelledby) on caption, code, deletion, emphasis, generic, insertion, paragraph, presentation, strong, subscript, superscript. Drupal html.html.twig outputs <html{{ html_attributes }}> and a skip link. Drupal core NodeViewBuilder builds the 'Read more<span class="visually-hidden"> about @title</span>' link. Pages Router i18n docs say Next adds lang to <html> automatically. Drupal.announce accepts polite (default) or assertive. Drupal.Message.add calls Drupal.announce unless options.announce is an empty string; message role is alert for error/warning, status otherwise.
CORRECTIONS to the researcher's notes: (1) Route announcer is a fallback chain, not a sequence. The source (app-router-announcer.tsx) uses document.title if set, else the first h1, and announces ONLY when the value differs from the previous one. Identical titles on two routes mean silence, not the same announcement. (2) Drupal '#title_display' => 'attribute' is implemented only for checkboxes and radios (CompositeFormElementTrait). On other elements it just means no label. 'none' is set internally by core when #title is missing (FormPreprocess), so it is real but undocumented as an author value. (3) WCAG 3.3.8 explicitly does not cover creating a username or account (registration), and CAPTCHAs outside authentication are out of its scope. F109 is the listed failure for preventing password or code re-entry in the same format. (4) In jsx-a11y 6.10.2, control-has-associated-label and anchor-ambiguous-text are 'off' even in flatConfigs.recommended and strict, and no-aria-hidden-on-focusable is in neither config. Enabling recommended does NOT give A11Y-04, A11Y-12 or A11Y-16 coverage. click-events-have-key-events, no-static-element-interactions, label-has-associated-control, anchor-is-valid, media-has-caption, no-autofocus, autocomplete-valid, html-has-lang, img-redundant-alt, iframe-has-title, tabindex-no-positive are on in recommended. (5) Tailwind v4: outline-none now emits outline-style: none (removes the outline), while outline-hidden emits a transparent 2px outline that survives forced-colors mode (the old v3 outline-none). (6) 2.2.2: a loading animation is explicitly exempt, and pausing only while hovered/focused is explicitly NOT a valid pause mechanism. (7) 3.3.7: the Understanding page says nothing about email-confirmation fields, so the researcher's 'essential only if the business requires it' is an opinion, not W3C text. Browser autofill does not satisfy 3.3.7. (8) React 18 does not know inert as a boolean (warns on inert={false}); React 19 does and rejects the old inert="" workaround.
STILL UNVERIFIED: whether Drupal core links inline error messages to fields via aria-describedby (drupal.org/i/3083103 suggests it does not); aria-invalid on invalid fields is tracked in drupal.org/i/2047075.
